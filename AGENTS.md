## Release and cleanup closure gate (mandatory)

This is the governing rule for future DexDiffusion release, repair, merge, deployment, cleanup and "finish it / stage commit push" work. It prevents repeating the November 2026 failure where "source ready" was mistaken for a completed release and the MacBook checkout was left dirty and behind. **Do not claim DONE merely because code, a PR, or CI is green.**

1. **Declare the completion scope before making changes.** Identify the named repository, active worktrees on both Macs, deliverable, source and deployed revisions, authorized mutations and real user-journey acceptance criteria. Separate SOURCE_READY, INTEGRATED, DEPLOYED, RUNTIME_VERIFIED and CLEAN_CLOSED. A request to finish the release includes the applicable stages; do not silently redefine it as "write a prompt" or "CI passed."
2. **Inventory and preserve Git state.** Inspect branch, remote, staged/unstaged/untracked files and worktree list before work **and again at closure**. Account for every relevant change: commit/push it to the correct branch, or mark it HELD with its path, owner/reason and recovery pointer. Never bulk-stage historical agent worktrees; never delete, reset, force-push, rebase away, or merge protected work to manufacture cleanliness. Unrelated dirty worktrees may be HELD; they must be disclosed, not silently absorbed or described as clean.
3. **Prove publication, not just a local commit.** After intended changes, inspect the staged diff and protections, commit and push when the task authorizes it, then independently read the *remote* branch SHA and PR state. Check applicable CI for the actual new SHA, not an ancestor. If there is no triggered CI, say so; it is not a passing run.
4. **Keep production and source identities distinct.** A merged main commit, deployed code SHA, docs-only closure commit, installed wrapper, EngineHost worker, live listener, model runtime and MacBook canonical publication may all differ. For an authorized deployment, prove actual running identity, generation, fallback/return when in scope, image integrity, receipts and pending queue. Source tests alone never prove production. Do not restart or perform a live drill unless the current task explicitly authorizes it.
5. **Close both machines and the worktree scope.** Reconcile MacBook main with remote main without destroying local changes; verify the Big Mac deployed worktree's exact revision and cleanliness without forcibly updating it to docs-only main. Archive superseded local changes on a separately named, pushed preservation branch when authorized; do not merge stale launcher versions over newer release code. Check the scoped worktrees with `python3 scripts/check_git_closure.py --repo . --branch main --inventory`; this check is **Git-only** and never substitutes for CI or production proof.
6. **Required final receipt:** report local and remote full SHAs, PR/CI state, deployed runtime evidence (or NOT VERIFIED), scoped checkout status, any HELD independent worktrees and the exact remaining requirements. Use COMPLETE only if every applicable acceptance gate was actually checked; otherwise PARTIAL, BLOCKED or SOURCE_READY with specific missing evidence. Never say "everything is pushed", "all clean" or "done" if those claims depend on uninspected machines or worktrees.

**Regression guard:** `scripts/test/test_git_closure.py` covers clean/pushed, staged/unstaged/untracked, remote divergence, unknown remote and held versus scoped worktrees. Keep it in the portable CI suite. The read-only checker must fail closed for the primary worktree and remote identity; it may report unrelated worktrees as HELD without modifying them.
