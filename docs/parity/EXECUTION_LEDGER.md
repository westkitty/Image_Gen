**Startup/background re-render focus loss — FIXED (2026-10-16).** Root cause: `dc-runtime.js` rebuilds the real DOM of any vnode-valued template slot (the whole Concept A shell, forms, panels) whenever its value changes — every `setState` produces a new vnode, so every background update (capability loads at startup, target switch, polling, SSE snapshots) remounted the prompt box and dropped focus, caret and scroll. Measured before the fix: 3+ prompt-textarea detaches at 30–60 ms intervals during the first 1–2 s after load, and typing lost focus in roughly 1 of 4 runs. Fix: the slot now captures the focused field before teardown (id → `data-dex-field` → child-index path → unique label/placeholder signature, with tag/type check) and restores focus, selection/caret and scroll on the new DOM; `DCRuntime.lastInstance` exposes the mounted instance for tests. Regression suite `tests/browser/form-stability.browser.js` (4 checks: 50-character typing through a 25 ms re-render storm, mid-text caret preserved, negative-prompt and numeric inputs, typing straight after load/target switch ×3); all 4 fail with the restore call disabled and pass with it (3 consecutive clean runs). Not covered: `sc-for`/`sc-if` rebuilt lists (they do not currently contain text fields) and fields inside the legacy V1–V3 template slots that are not vnode-valued (patched in place, never remounted).
Full regression after the fix: unit 648 pass / 0 fail / 1 skipped; browser form-stability 4/4, generate-sampling 9/9, prompt-language 3/3, prompt-styles 5/5, concept-a 8/8, edit 24/24, voice-drama 8/8, drama-studio 9/9, matrix 180/180.
